# 개인 PC에서 HAVS 실행하기

2026년 10월 21일 수요일(한국 시간)에 로컬 PC를 설정할 때 사용할 안내입니다. 클라우드의 Workers + D1과 PC의 Node + SQLite는 각각 실행할 수 있습니다. 클라우드 게시 여부는 실제 접속 주소에서 확인합니다.

## 설치와 시작

PC에 Node.js 24와 Git을 설치하고 HAVS 코드가 있는 폴더에서 터미널을 엽니다. 현재 앱 코드는 `codex/havs-server-workspace` 브랜치에 있습니다. `main`에는 아직 README만 있으므로 아래 브랜치를 지정합니다.

```bash
git clone --branch codex/havs-server-workspace https://github.com/TonyNobleHam/HAVs.git
cd HAVs
node --version
npm ci
npm run dev:full
```

이미 코드가 있다면 해당 폴더에서 `node --version`부터 실행합니다. `npm ci`에는 인터넷이 필요합니다. 설치가 끝나면 로컬 사용에는 Cloudflare 로그인이나 D1 연결이 필요하지 않습니다.

브라우저에서 **http://localhost:5173**에 접속합니다. `dev:full`은 화면 서버(5173)와 로컬 API(3001)를 함께 실행합니다. 계정 없이 확인하려면 **예시로 둘러보기**를 선택합니다.

처음에는 `APP_ORIGIN`, `HOST`, `VITE_HOST`, `PORT`, `HAVS_DATA_DIR`을 따로 지정하지 않고 기본 설정을 사용합니다. 이미 지정한 값이 있다면 클라우드 운영 주소나 데이터 경로가 로컬 실행에 섞이지 않도록 확인합니다.

## 로컬 계정 만들기

앱을 켠 상태에서 두 번째 터미널을 같은 HAVS 폴더에 열고 이메일과 이름을 본인 정보로 바꿔 실행합니다.

```bash
npm run admin -- create-user --email owner@example.com --name '운영자'
```

비밀번호는 숨김 터미널 프롬프트에서 12–128자로 입력합니다. 비밀번호를 명령행, 파일 또는 대화창에 적지 않습니다. 계정을 만든 뒤 로그인하고 **빈 작업 공간으로 시작**을 선택하면 실제 기록을 입력할 수 있습니다.

이 명령으로 만든 계정은 **이 PC의 SQLite에만** 생성됩니다. 같은 이메일을 사용해도 클라우드의 계정이나 기록과 연결되지 않습니다. 클라우드 계정은 클라우드 운영 절차에 따라 별도로 준비합니다.

## 저장 위치와 데이터 옮기기

| 사용 방식 | 저장 위치 | 다른 환경과 자동 동기화 |
| --- | --- | --- |
| PC에서 로그인 | 기본 `data/havs.sqlite` | 없음 |
| 클라우드에서 로그인 | 배포된 서비스의 D1 | PC SQLite와 동기화되지 않음 |
| 예시로 둘러보기 | 해당 브라우저의 로컬 저장소 | 없음 |

계정별 작업 공간에는 공구, 프로젝트, 평가가 들어갑니다. JSON으로 필요한 작업 공간을 명시적으로 옮길 수 있습니다.

1. 원본 환경에서 옮길 **계정**으로 로그인합니다.
2. **가이드 · 평가 기준 → 전체 데이터 백업**으로 JSON을 내려받습니다.
3. 대상 환경에서 데이터를 받을 **계정**으로 로그인하고, 대상의 기존 작업 공간도 먼저 JSON으로 백업합니다.
4. **JSON 백업 복원**에서 원본 파일을 선택하고 교체할 내용을 확인합니다.
5. 서버 저장 완료를 확인한 뒤 새로고침하여 공구·프로젝트·평가가 유지되는지 확인합니다.

복원은 대상 계정의 작업 공간을 **교체**하며 자동 병합하지 않습니다. 다른 계정의 작업 공간에는 적용되지 않습니다. JSON에는 계정·비밀번호·세션·초대가 포함되지 않으며, 원본 환경의 데이터도 그대로 남습니다. 가져올 파일은 5,000,000바이트 이하이고, 로그인 모드에서는 공백 등을 제거한 저장용 작업 공간 JSON도 1,900,000바이트 이하여야 합니다.

## 로컬 전체 백업과 복구

JSON은 작업 공간 이동용입니다. 로컬 계정까지 보존하려면 SQLite 전체 백업을 별도로 만듭니다. 먼저 PC의 안전한 백업 폴더를 준비하고 아래 출력 경로를 그 폴더의 새 파일명으로 바꿉니다.

```bash
npm run admin -- backup --output /path/to/backups/havs-2026-10-21.sqlite
```

Windows에서는 `C:/Users/사용자명/HAVS-backups/havs-2026-10-21.sqlite`처럼 본인의 실제 경로를 사용합니다. API와 관리 명령은 같은 HAVS 폴더 및 같은 `HAVS_DATA_DIR`을 사용해야 합니다. 백업은 실행 중에도 만들 수 있지만 실행 중인 `data/havs.sqlite`만 파일 탐색기로 복사하지 않습니다.

백업에는 계정과 작업 기록이 포함되므로 접근을 제한하고 PC 외부의 안전한 저장 장치에도 사본을 보관합니다. DB, 백업, 비밀번호 파일을 GitHub에 올리지 않습니다.

전체 복구 시에는 먼저 `dev:full` 터미널에서 **Ctrl+C**로 앱을 종료하고 같은 DB를 사용하는 모든 프로세스를 멈춥니다. 기존 백업을 보관한 뒤 실행합니다.

```bash
node scripts/restore.mjs --source /path/to/backups/havs-2026-10-21.sqlite --confirm-offline
npm run dev:full
```

전체 복구는 로컬 계정과 기록을 복구하며 기존 세션은 폐기하므로 다시 로그인해야 합니다. 이 SQLite 파일을 D1로 그대로 업로드하지 않습니다. PC와 클라우드 사이의 작업 공간 이동에는 위 JSON 절차를 사용합니다.

## 접속 범위와 종료

기본 접속 주소는 `localhost`이며 화면 서버와 API는 기본적으로 `127.0.0.1`에 바인딩되어 같은 PC에서만 접근할 수 있습니다. 로컬 사용을 위해 공유기 포트 전달이나 인터넷 공개 설정을 추가하지 않습니다.

같은 LAN의 다른 기기로 접속하려는 경우에만 `VITE_HOST=0.0.0.0`으로 화면 서버 바인딩을 바꾸고, 실제 PC 주소에 맞는 `APP_ORIGIN`을 지정합니다. 예: `http://192.168.0.10:5173`처럼 프로토콜·호스트·포트를 포함하고 끝의 `/`는 제외합니다. PC 방화벽은 신뢰하는 LAN에만 5173 접근을 허용합니다. API의 `HOST`는 기본값을 유지하며 3001 포트를 직접 공개하지 않습니다.

PC가 절전·종료되거나 앱을 닫으면 로컬 앱은 멈춥니다. PC의 인터넷이 끊겨도 같은 PC의 로컬 실행은 계속 가능하지만, 다른 기기의 접근은 네트워크 연결에 달려 있습니다. 배포된 Cloudflare 서비스는 PC의 전원 상태와 별개로 동작합니다. 로컬 DB 파일은 앱 종료 후에도 유지되지만 디스크 손실에 대비해 백업해야 합니다.

Docker는 선택 사항입니다. 현재 Compose 구성은 실제 HTTPS 도메인과 Caddy를 사용하는 서버 운영용이므로 단순한 PC 사용에는 위 개발 실행을 사용합니다. Docker 운영 구성은 [배포 안내](deployment.md)를 참고하세요.
