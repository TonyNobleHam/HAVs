# HAVS Workspace

공구의 손·팔 진동(Hand–Arm Vibration)과 소음 노출을 기록하는 한국어 웹 앱입니다. 제공된 HAVBase 참고 화면의 공구 관리, 트리거 시간 입력, 작업자 평가 및 프로젝트 보고서 흐름을 바탕으로 구현한 첫 버전입니다.

화면 캡처: [대시보드](docs/screenshots/dashboard.png) · [노출 평가](docs/screenshots/assessment.png) · [모바일](docs/screenshots/mobile.png).

## 실행

Node.js 24 권장(최소 22.18), npm을 사용합니다.

```bash
cd /workspace/HAVs
npm ci
npm run dev
```

개발 서버는 기본 5173 포트에서 실행됩니다. 배포용 정적 파일은 `npm run build`로 `dist/`에 생성하며, `npm run preview`로 해당 결과물을 확인할 수 있습니다. 정적 웹 호스트에 `dist/`를 배포하면 됩니다. 별도의 DB, API 키, 외부 폰트 서버는 필요하지 않습니다. 클라우드 환경 게시와 웹 앱 배포는 서로 다른 작업입니다.

`.npmrc`는 제한된 클라우드 작업 공간에서도 설치할 수 있도록 npm 캐시를 저장소 내부의 무시되는 `.npm-cache/`에 보관합니다. 각 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하며, 별도 Git worktree가 필요하지 않습니다.

## 첫 버전 기능

- **대시보드:** 오늘의 평가, 최근 7일 일별 최대 A(8), 진동 위험 수준 분포, 공구별 진동 기여도, 점검 예정 안내. 모든 수치는 저장된 기록에서 계산합니다.
- **공구 데이터베이스:** 등록·검색·분류·수정·삭제, 진동 합성값과 LAeq, 데이터 출처와 작업 조건, 예시 데이터 표시, 점검일 관리.
- **일일 노출 평가:** 여러 공구의 실제 사용 시간을 합산한 A(8), 노출 점수, 소음 LEX,8h의 실시간 계산. 같은 작업자 이름·날짜의 평가 중복을 방지합니다. 하루 전체 작업을 하나의 평가에 입력합니다.
- **과거 기록 보존:** 평가에는 당시 공구의 수치·이름·출처가 복사됩니다. 이후 공구를 수정하거나 삭제해도 과거 결과는 바뀌지 않습니다. 평가 자체의 수정·삭제는 별도로 가능합니다.
- **프로젝트:** 현장과 담당자 등록·수정, 프로젝트별 기록과 기간 필터, CSV 다운로드, 브라우저 인쇄 및 PDF 저장.
- **백업·복원:** 전체 작업 공간을 JSON으로 내보내고 검증 후 복원합니다. 데이터 교체·전체 초기화에는 확인 절차가 있습니다.
- **모바일 화면:** 접이식 메뉴, 공구 입력, 사용 시간 변경, 보고서 확인을 지원합니다.

첫 실행 시 **가상의 공구 8개, 프로젝트 3개, 평가 12개**를 제공합니다. 모델명과 진동·소음값은 기능 시연용이며 특정 제조사의 실제 측정 데이터가 아닙니다. 가이드에서 백업 후 `새 작업 공간으로 시작`을 선택하면 실제 데이터를 입력할 수 있습니다.

## 저장 범위

데이터는 현재 브라우저의 `localStorage`(`havs.workspace.v1`)에 저장됩니다. 새로고침해도 유지되지만 다른 기기·브라우저·주소와 동기화되지 않습니다. 브라우저 저장 데이터를 삭제하면 사라질 수 있으므로 JSON 백업을 보관하세요. 여러 탭에서의 동시 편집은 지원하지 않습니다. 읽기 실패 시 기존 저장 데이터를 자동으로 덮어쓰지 않으며, 저장 실패도 화면에 알립니다.

인증·다중 사용자·서버 DB·자동 이메일·검증된 상용 공구/PPE 데이터베이스·청력 보호구 감쇠 계산·실측 기반 공구 노후화 통계는 이 버전에 포함되지 않습니다. 공구 점검 일정은 사용자가 기록하는 날짜이며, 진동 측정에 기반한 자동 수명 예측이 아닙니다.

## 계산 기준과 범위

영국 HSE의 참고 기준을 사용하며 한국 법적 적합성이나 의학적 진단을 제공하지 않습니다.

| 항목                                  | 계산 / 참고 기준                                           |
| ------------------------------------- | ---------------------------------------------------------- |
| 진동 A(8)                             | `sqrt(sum(a² × T_minutes) / 480)`                          |
| 진동 노출 점수                        | `sum(a² × T_minutes) / 30`, 100점 = 조치값, 400점 = 한계값 |
| 진동 조치값 / 한계값                  | A(8) 2.5 / 5 m/s²                                          |
| 해당 공구 단독 사용 시 기준 도달 시간 | `480 × (threshold / a)²` 분                                |
| 소음 LEX,8h                           | `10 × log10(sum(T_minutes / 480 × 10^(LAeq / 10)))`        |
| 소음 하위 / 상위 조치값               | 80 / 85 dB(A)                                              |

- `a`는 공구 사용 중 3축 주파수 가중 진동 합성값입니다. 사용 시간은 근무 시간이 아닌 실제 트리거 시간입니다.
- 판정은 반올림 전 수치로 계산합니다. 표시 수치는 반올림되므로 기준에 매우 가까운 값은 표시와 판정의 차이가 있을 수 있습니다.
- 소음값이 없는 공구의 사용 시간이 0보다 크면 일일 소음 결과를 산출하지 않습니다. 미입력을 무음으로 처리하지 않습니다.
- 소음은 보호구 감쇠, 피크 소음 및 미기록 작업을 반영하지 않습니다. 보호구 착용 효과까지 고려해야 하는 87 dB(A)의 법적 한계 준수 판정은 하지 않습니다.
- 대시보드 공구별 기여도는 선택한 프로젝트의 최근 7일 전체 기록에 대한 `a² × T` 비중입니다. 작업자들의 A(8)을 합산한 일일 노출값이 아닙니다.
- 실제 작업에 사용하려면 대표성 있는 측정 데이터, 작업 조건, 현지 법령 및 전문가의 검토가 필요합니다.

출처: [HSE 진동 노출 계산](https://www.hse.gov.uk/vibration/hav/readyreckoner.htm), [HSE 소음 규정](https://www.hse.gov.uk/noise/regulations.htm).

## 검증

```bash
npm test             # 계산 경계값, 누적 에너지, CSV와 백업 검증
npm run build        # TypeScript 검사 + 프로덕션 빌드
npm run test:e2e     # 실제 Chromium 사용자 흐름
```

브라우저 테스트는 시스템의 `/usr/bin/chromium`을 사용합니다. 다른 위치는 `CHROMIUM_PATH`로 지정할 수 있습니다. 시스템 Chromium이 없으면 `npx playwright install chromium` 후 Playwright의 기본 브라우저를 사용합니다. 테스트 서버는 자동으로 실행되며, 개발 중에는 기존 5173 포트의 Vite 서버를 재사용합니다.

핵심 코드는 `src/domain.ts`(계산·백업 검증·CSV), `src/storage.ts`(저장), `src/seed.ts`(가상 예시), `src/App.tsx`(화면·사용 흐름), `src/styles.css`(반응형·인쇄)로 나뉩니다.
