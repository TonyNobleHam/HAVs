# HAVS Workspace

공구의 손·팔 진동(Hand–Arm Vibration)과 소음 노출을 기록하는 한국어 웹 앱입니다. 제공된 HAVBase 참고 화면의 공구 관리, 트리거 시간 입력, 작업자 평가 및 프로젝트 보고서 흐름을 바탕으로 구현했습니다. 로그인한 사용자의 기록을 서버에 저장하고 다른 기기에서도 사용할 수 있습니다.

화면 캡처: [로그인](docs/screenshots/login.png) · [모바일 로그인](docs/screenshots/login-mobile.png) · [대시보드](docs/screenshots/dashboard.png) · [노출 평가](docs/screenshots/assessment.png) · [모바일](docs/screenshots/mobile.png).

## 실행

Node.js 24 이상과 npm을 사용합니다. Node 내장 SQLite를 사용하므로 별도 DB 서버나 API 키는 필요하지 않습니다.

```bash
cd /workspace/HAVs
npm ci
npm run dev:full
```

`http://localhost:5173`에 접속합니다. 다른 터미널에서 첫 계정을 생성합니다. 이메일과 이름을 본인 것으로 바꾸고, 비밀번호는 숨김 터미널 프롬프트에서 입력합니다.

```bash
npm run admin -- create-user --email owner@example.com --name '운영자'
```

공개 회원가입은 없으며 추가 계정은 `npm run admin -- create-invite --email colleague@example.com`으로 발급한 초대로 가입합니다. 비밀번호는 12–128자입니다. 기본 계정이나 기본 비밀번호는 제공하지 않습니다.

`dev:full`은 API(3001)와 Vite(5173)를 함께 실행합니다. 기본 주소와 다른 포트 미리보기 URL을 사용할 때는 `APP_ORIGIN`을 실제 브라우저 출처로 설정합니다. `npm run dev`는 화면 개발용 Vite만 실행합니다. 로그인 없이 확인하려면 **예시로 둘러보기** 또는 `http://localhost:5173/?demo=1`을 사용합니다.

배포용 화면은 `npm run build`로 `dist/`에 생성합니다. Node 서버가 API와 `dist/`를 함께 제공합니다. **로그인·서버 저장에는 Node 서버와 지속 데이터 볼륨이 필요합니다.** 정적 파일만 배포하면 서버 기능을 사용할 수 없습니다. Docker Compose + Caddy HTTPS 구성, 계정 관리, 백업·복구는 [배포 안내](docs/deployment.md)를 참고하세요. 공개 배포에는 사용할 도메인과 서버가 필요하며, Codex 클라우드 환경 게시와 웹 앱 배포는 별개입니다.

`.npmrc`는 제한된 클라우드 작업 공간에서도 설치할 수 있도록 npm 캐시를 저장소 내부의 무시되는 `.npm-cache/`에 보관합니다. 각 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하며, 별도 Git worktree가 필요하지 않습니다.

## 기능

- **로그인·서버 저장:** 초대 가입, 계정별 SQLite 작업 공간, 다른 기기에서 접근, 세션 쿠키·출처·CSRF 검사, 서버 CLI를 통한 비밀번호 재설정.
- **대시보드:** 오늘의 평가, 최근 7일 일별 최대 A(8), 진동 위험 수준 분포, 공구별 진동 기여도, 점검 예정 안내. 모든 수치는 저장된 기록에서 계산합니다.
- **공구 데이터베이스:** 등록·검색·분류·수정·삭제, 진동 합성값과 LAeq, 데이터 출처와 작업 조건, 예시 데이터 표시, 점검일 관리.
- **일일 노출 평가:** 여러 공구의 실제 사용 시간을 합산한 A(8), 노출 점수, 소음 LEX,8h의 실시간 계산. 같은 작업자 이름·날짜의 평가 중복을 방지합니다. 하루 전체 작업을 하나의 평가에 입력합니다.
- **과거 기록 보존:** 평가에는 당시 공구의 수치·이름·출처가 복사됩니다. 이후 공구를 수정하거나 삭제해도 과거 결과는 바뀌지 않습니다. 평가 자체의 수정·삭제는 별도로 가능합니다.
- **프로젝트:** 현장과 담당자 등록·수정, 프로젝트별 기록과 기간 필터, CSV 다운로드, 브라우저 인쇄 및 PDF 저장.
- **백업·복원:** 전체 작업 공간을 JSON으로 내보내고 검증 후 복원합니다. 데이터 교체·전체 초기화에는 확인 절차가 있습니다.
- **모바일 화면:** 접이식 메뉴, 공구 입력, 사용 시간 변경, 보고서 확인을 지원합니다.

로그인 후 **빈 작업 공간으로 시작**하거나 **예시 데이터로 시작**을 선택합니다. 예시는 **가상의 공구 8개, 프로젝트 3개, 평가 12개**입니다. 모델명과 진동·소음값은 기능 시연용이며 특정 제조사의 실제 측정 데이터가 아닙니다. 이전 브라우저 기록은 **이 브라우저의 데이터 가져오기**로 서버에 옮길 수 있습니다. 실제 검증에는 측정 출처가 있는 공구 데이터와 작업 시간이 필요합니다.

## 저장 범위

로그인 모드의 데이터는 서버의 `data/havs.sqlite`에 계정별로 저장됩니다. Docker에서는 지속 볼륨을 사용합니다. 같은 계정의 다른 기기에서 기록을 확인할 수 있으며, 동시 편집 충돌 시 상대 기록을 자동 덮어쓰지 않고 충돌을 알립니다. 서버 저장 실패 상태에서는 변경 사항이 메모리에만 남을 수 있으므로 화면을 닫기 전에 JSON 백업을 내보냅니다. 전체 서버 복구에는 계정 정보까지 포함한 SQLite 백업이 필요합니다.

**예시로 둘러보기** 모드에서는 현재 브라우저의 `localStorage`(`havs.workspace.v1`)에 저장합니다. 이 모드의 기록은 다른 기기와 동기화되지 않습니다. 브라우저 저장 데이터를 삭제하면 사라질 수 있으므로 JSON 백업을 보관하세요. 기존 로컬 기록을 가져와도 원본은 지우지 않습니다.

조직 공동 작업 공간·역할별 권한·MFA/SSO·자동 이메일·검증된 상용 공구/PPE 데이터베이스·청력 보호구 감쇠 계산·실측 기반 공구 노후화 통계는 이 버전에 포함되지 않습니다. 공구 점검 일정은 사용자가 기록하는 날짜이며, 진동 측정에 기반한 자동 수명 예측이 아닙니다.

## 계산 기준과 범위

영국 HSE의 참고 기준을 사용하며 한국 법적 적합성이나 의학적 진단을 제공하지 않습니다.

| 항목                                  | 계산 / 참고 기준                                           |
| ------------------------------------- | ---------------------------------------------------------- |
| 진동 A(8)                             | `sqrt(sum(a² × T_minutes) / 480)`                          |
| 진동 노출 점수                        | `sum(a² × T_minutes) / 30`, 100점 = 조치값, 400점 = 한계값 |
| 진동 조치값 / 한계값                  | A(8) 2.5 / 5 m/s²                                          |
| 해당 공구 단독 사용 시 기준 도달 시간 | `480 × (threshold / a)²` 분                                |
| 소음 LEX,8h                           | `10 × log10(sum(T_minutes / 480 × 10^(LAeq / 10)))`        |
| 소음 하위 / 상위 조치값               | 80 / 85 dB(A)                                              |

- `a`는 공구 사용 중 3축 주파수 가중 진동 합성값입니다. 사용 시간은 근무 시간이 아닌 실제 트리거 시간입니다.
- 판정은 반올림 전 수치로 계산합니다. 표시 수치는 반올림되므로 기준에 매우 가까운 값은 표시와 판정의 차이가 있을 수 있습니다.
- 소음값이 없는 공구의 사용 시간이 0보다 크면 일일 소음 결과를 산출하지 않습니다. 미입력을 무음으로 처리하지 않습니다.
- 소음은 보호구 감쇠, 피크 소음 및 미기록 작업을 반영하지 않습니다. 보호구 착용 효과까지 고려해야 하는 87 dB(A)의 법적 한계 준수 판정은 하지 않습니다.
- 대시보드 공구별 기여도는 선택한 프로젝트의 최근 7일 전체 기록에 대한 `a² × T` 비중입니다. 작업자들의 A(8)을 합산한 일일 노출값이 아닙니다.
- 실제 작업에 사용하려면 대표성 있는 측정 데이터, 작업 조건, 현지 법령 및 전문가의 검토가 필요합니다.

출처: [HSE 진동 노출 계산](https://www.hse.gov.uk/vibration/hav/readyreckoner.htm), [HSE 소음 규정](https://www.hse.gov.uk/noise/regulations.htm).

## 검증

```bash
npm test             # 계산, 백업 검증, 서버 인증·격리·저장 검증
npm run build        # TypeScript 검사 + 프로덕션 빌드
npm run test:e2e     # 실제 Chromium 사용자 흐름
npm run test:e2e:server # 로그인·서버 저장·브라우저 간 충돌 흐름
```

브라우저 테스트는 시스템의 `/usr/bin/chromium`을 사용합니다. 다른 위치는 `CHROMIUM_PATH`로 지정할 수 있습니다. 시스템 Chromium이 없으면 `npx playwright install chromium` 후 Playwright의 기본 브라우저를 사용합니다. 예시 모드 테스트는 기존 5173 포트의 Vite를 재사용할 수 있습니다. 서버 모드 테스트는 별도의 5174/3002 포트와 임시 DB·테스트 계정을 사용하고 종료 시 삭제합니다.

핵심 코드는 `src/domain.ts`(계산·백업 검증·CSV), `src/storage.ts`(브라우저·서버 저장 흐름), `src/api.ts`(API 호출), `src/Auth.tsx`(로그인·초대·첫 작업 공간), `src/seed.ts`(가상 예시), `src/App.tsx`(화면·사용 흐름), `src/styles.css`(반응형·인쇄), `server/`(인증 API·SQLite·관리 CLI)로 나뉩니다.
